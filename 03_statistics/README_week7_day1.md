# 第7周 Day1：A/B测试实验设计与指标定义

## 一、学习目标

本次学习如何把业务问题转化为可执行的A/B测试方案，并在查看实验结果前确定分组、指标口径和护栏阈值。

主要内容：

- 对照组与实验组
- 原假设与备择假设
- 实验单位
- 随机分流与固定分组
- 核心指标与护栏指标
- 指标分子、分母口径
- 绝对提升与相对提升
- 预设护栏阈值
- 初步实验决策

## 二、业务问题与实验假设

业务问题：

```text
新版结算页能否提高支付转化率？
```

实验假设：

```text
新版结算页能够提高支付转化率，
并且不会明显提高退款率、页面错误率和支付失败率。
```

统计假设：

```text
H0：B组真实转化率没有高于A组
H1：B组真实转化率高于A组
```

## 三、实验分组

- A组：当前旧版结算页，对照组。
- B组：新版结算页，实验组。
- 实验单位：用户。
- 分流方式：按照user_id随机50/50分流。
- 固定分组：同一用户在实验期间始终进入同一组。

固定分组可以避免同一用户交叉看到两个版本造成实验污染，并确保用户行为能够归因到一个版本。

随机分流用于尽量减少两组用户结构和混杂因素差异，但不能保证两组在所有特征上完全一致。

## 四、指标口径

核心指标：支付转化率。

```text
支付转化率
= 完成支付的符合条件独立用户数
÷ 成功看到结算页的符合条件独立用户数
```

因为实验单位是用户，所以分子和分母都使用独立用户。不能分子统计订单、分母统计用户，否则同一用户多笔订单会造成统计口径不一致。

护栏指标：

- 退款率
- 页面错误率
- 支付失败率
- 客单价

护栏指标用于防止提高核心指标的同时伤害其他重要业务结果。

## 五、排除规则

本实验排除：

- 员工账号
- 测试账号
- 机器人
- 异常流量
- 未真正加载结算页的记录

排除规则必须在实验开始前确定，并对A、B两组一致执行。

## 六、基础实验结果

| 指标 | A组 | B组 |
|---|---:|---:|
| 曝光用户数 | 5000 | 5100 |
| 支付用户数 | 400 | 459 |
| 支付转化率 | 8.00% | 9.00% |
| 退款用户数 | 20 | 35 |
| 退款率 | 5.00% | 7.63% |
| 页面错误用户数 | 50 | 80 |
| 页面错误率 | 1.00% | 1.57% |
| 流量占比 | 49.50% | 50.50% |

两组流量规模接近预定的50/50分流，但这只是初步检查，不能单独证明随机分流完全正常。

## 七、绝对提升与相对提升

支付转化率从8%提高到9%。

绝对提升：

```text
9% - 8% = 1个百分点
```

相对提升：

```text
(9% - 8%) ÷ 8% = 12.5%
```

“百分点”和“百分比”不能混用。

正确表述：

> B组支付转化率相比A组绝对提高1个百分点，相对提高12.5%。

## 八、护栏阈值

实验前预设：

```text
退款率允许增加不超过1个百分点
页面错误率允许增加不超过0.2个百分点
```

实际结果：

```text
退款率增加2.63个百分点
页面错误率增加0.57个百分点
```

两项护栏均未通过。

护栏阈值必须在实验前确定，不能看到结果后为了让B组通过而放宽标准。

## 九、初步决策

虽然B组支付转化率更高，但退款率和错误率均超过预设容忍范围，因此初步决策为：

```text
暂缓上线：护栏指标超过预设范围
```

即使护栏通过，也不能立即上线。还需要检查：

- 分流比例是否异常
- 样本量是否足够
- 置信区间
- 统计显著性
- 实际业务提升是否足够大
- 实验周期是否完整

## 十、常见错误

1. 把VIP用户全部放入B组、普通用户全部放入A组。
2. 同一用户在实验期间交叉看到A、B版本。
3. 分子统计订单、分母统计用户。
4. 实验开始后不断修改核心指标和分母口径。
5. 只看转化率，不检查退款率和错误率。
6. 把绝对提升1个百分点说成提升1%。
7. 看到B组点估计更高就提前停止实验。

## 十二、今日结论

```text
业务问题
→ 提出实验假设
→ 确定实验单位
→ 随机且固定分组
→ 预先定义核心指标
→ 预先定义护栏指标和阈值
→ 检查核心指标和护栏指标
→ 进行统计检验
→ 结合业务价值决定是否上线
```

A/B测试的目标不是寻找一个看起来更高的数字，而是在可比实验条件下判断变化是否真实、是否有业务价值、是否带来不可接受的副作用。
