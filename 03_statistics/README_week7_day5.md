# 第7周 Day5：A/B 测试综合复盘与实验报告

## 1. 今日学习目标

将实验设计、数据质量、SRM、核心指标、置信区间、显著性检验、样本量、统计功效、业务价值和护栏指标整理成一份完整、可复核的 A/B 测试报告。

## 2. 报告结构

完整的实验报告包括：

1. 业务问题与实验假设。
2. 对照组、实验组、实验单位和指标口径。
3. 数据质量与 SRM 检查。
4. A、B 两组核心指标结果。
5. 置信区间和显著性检验。
6. 样本量与统计功效判断。
7. 业务显著性判断。
8. 护栏指标检查。
9. 综合结论与后续行动。

## 3. 报告表达方法

实验结论应按照“事实、解释、建议”表达：

- 事实：B组转化率为9%，A组为8%，样本差异为1个百分点。
- 解释：p-value 为0.0717，差异的95%置信区间包含0，目前证据不足以排除随机波动。
- 建议：不能认定B组真实有效，应暂停上线，优先调查护栏异常，并在修复后继续积累样本、重新验证。

不能把观察结果直接写成因果结论，也不能把“未达到统计显著”写成“已经证明无效”。

## 4. 数据来源

Day5 脚本直接读取前4天的分析结果：

- Day1：A、B两组基础指标与护栏指标。
- Day2：SRM、置信区间和两比例检验。
- Day3：MDE、统计功效和样本量方案。
- Day4：统计显著性、业务显著性、护栏指标和最终决策。

这种方式减少了重复录入，也降低了人工复制数字产生错误的风险。

## 5. 一致性验证

报告生成前检查：

- A组转化率是否等于支付人数除以曝光人数。
- B组转化率是否等于支付人数除以曝光人数。
- 两组流量占比合计是否为100%。
- B组转化率减A组转化率是否等于保存的绝对提升。

四项检查全部通过。代码使用允许误差判断小数是否一致，避免浮点数精度问题。

## 6. 核心实验结果

- A组为对照组，转化率为8%。
- B组为实验组，转化率为9%。
- 绝对提升为1个百分点，相对提升为12.5%。
- SRM p-value 为0.3197，暂未发现明显分流异常。
- 效果检验 p-value 为0.0717，未达到0.05显著性水平。
- 差异95%置信区间为-0.09至2.09个百分点，包含0。
- 实际每组约5,000人，低于基准方案要求的每组12,208人。
- 退款率增加2.63个百分点，超过允许的1个百分点。
- 错误率增加0.57个百分点，超过允许的0.2个百分点。

## 7. 综合结论

B组转化率样本提升1个百分点，观察结果具有潜在业务价值。但是核心指标未达到统计显著，样本量不足，且退款率和错误率护栏均未通过。

当前既不能宣布B组有效，也不能宣布B组无效。最终建议是暂停上线，优先调查并修复护栏指标异常；修复后重新实验，继续积累至预设样本量，再综合判断。

## 8. 护栏指标的判断

“护栏指标发生变化”和“护栏指标未通过”含义不同：

- 指标发生变化但仍在预设容忍范围内，可以记为护栏通过。
- 护栏未通过已经表示变化超过预设容忍范围，应暂停上线并调查。

不能在看到结果后为了上线而放宽护栏阈值。

## 9. 上线策略

即使数据质量、样本量、统计显著性、业务显著性和护栏指标全部通过，也不应立即100%全量上线。更稳妥的做法是：

1. 小流量灰度发布。
2. 持续监控核心指标和护栏指标。
3. 观察线上长期效果和不同用户群体表现。
4. 确认稳定后逐步扩大流量。
5. 保留异常回滚能力。

## 10. 今日代码知识点

- 使用 `pd.read_csv()`读取前序分析结果。
- 使用条件筛选和 `.iloc[0]`提取指定记录。
- 使用 `f-string`自动填充报告数据。
- 使用允许误差验证浮点数计算是否一致。
- 使用 `.all()`判断多项检查是否全部通过。
- 使用 `write_text(..., encoding="utf-8")`生成中文 Markdown 报告。
