# 第11周模型设计：在线教育付费分析

## 1. 业务问题

在线教育平台希望每天按课程类别、获客渠道和学员城市分析：

- 有效付费订单数；
- 购买课程数量；
- 实付收入；
- 各渠道目标完成率与预警状态。

一个订单可以同时购买多门课程。

## 2. 输入数据

- 订单主表：订单号、下单日期、渠道 ID、学员城市 ID、订单状态。
- 订单课程明细：订单号、课程 ID、课程数量、单价、折扣率。
- 课程资料：课程 ID、课程名称、课程类别。
- 渠道资料：渠道 ID、渠道名称、渠道类别。
- 城市资料：城市 ID、城市名称、省份、区域。
- 渠道目标：日期、渠道 ID、目标收入。

## 3. DWD 星型模型

### 3.1 付费事实表

粒度：每笔订单中的每门课程一行。

建议字段：

| 字段 | 作用 |
|---|---|
| order_id | 订单标识；计算订单数时去重计数 |
| date_id | 关联日期维度 |
| course_id | 关联课程维度 |
| channel_id | 关联渠道维度 |
| city_id | 关联城市维度 |
| course_quantity | 购买课程数量，可求和 |
| unit_price | 单价，不直接求和 |
| discount_rate | 折扣率，不直接求和 |
| net_revenue | 实付收入，可求和 |

指标规则：

- 有效付费订单数：对 `order_id` 去重计数。
- 购买课程数量：汇总 `course_quantity`。
- 实付收入：汇总 `net_revenue`。
- 单价和折扣率相加没有明确业务含义；折扣分析需要明确平均或加权口径。

### 3.2 日期维度

粒度：每个日期一行。

字段：`date_id`、完整日期、年份、季度、月份、日、星期。

### 3.3 课程维度

粒度：每门课程一行。

字段：`course_id`、课程名称、课程类别。

### 3.4 渠道维度

粒度：每个渠道一行。

字段：`channel_id`、渠道名称、渠道类别。

### 3.5 城市维度

粒度：每个城市一行。

字段：`city_id`、城市名称、省份、区域。

### 3.6 模型关系

```text
                     日期维度
                         |
课程维度 —— 付费事实表 —— 渠道维度
                         |
                     城市维度
```

每张维度表的一条记录可以对应付费事实表中的多条记录。

## 4. 分层设计

### ODS

原样接收订单主表、订单课程明细、课程资料、渠道资料、城市资料和渠道目标数据，保留重复记录、异常文本和原始状态以便追溯。

### DWD

完成去重、类型转换、状态统一、有效付费筛选和实付收入计算，形成付费事实表及标准化维度表。

付费事实表粒度：每笔订单中的每门课程一行。

### DWS

建立通用付费主题汇总表：

| 字段 | 说明 |
|---|---|
| date_id | 日期 |
| course_category | 课程类别 |
| channel_id | 渠道 |
| city_id | 城市 |
| paid_order_count | 去重付费订单数 |
| course_quantity | 课程数量 |
| net_revenue | 实付收入 |

粒度：每个日期、每个课程类别、每个渠道、每个城市一行。

用途：供课程、渠道和地区等多个分析报表复用。

### ADS

建立管理层渠道目标看板表：

| 字段 | 说明 |
|---|---|
| date_id | 日期 |
| channel_id | 渠道 |
| actual_revenue | 实际收入 |
| target_revenue | 目标收入 |
| completion_rate | 目标完成率 |
| alert_status | 预警状态 |

粒度：每个日期、每个渠道一行。

用途：只服务于管理层渠道目标看板。

## 5. 数据流

```text
订单、课程、渠道、城市、目标原始数据
                ↓
              ODS
                ↓ 去重、转换、统一状态、有效付费筛选
              DWD
                ↓ 按日期×课程类别×渠道×城市汇总
              DWS
                ↓ 结合渠道目标计算完成率与预警
              ADS
                ↓
          管理层渠道目标看板
```

## 6. 验证清单

1. DWD 每一行能否唯一解释为“某订单中的某门课程”。
2. 同一订单购买多门课程时，订单数是否使用订单号去重计数。
3. 维度表是否只保存对象 ID 和描述属性，没有混入订单数量或收入。
4. DWS 汇总后，订单数、课程数量和实付收入能否回算到 DWD 总体。
5. ADS 是否同时保留日期和渠道粒度，避免把“每日各渠道”误写成“每个渠道一行”。
6. 目标完成率的分子、分母和零目标处理是否明确。

## 7. 能力说明

本设计由课堂分步练习和纠错结果整理而成。学习者能够解释各层用途，并能在提示后完成事实表、维度表和汇总粒度设计；尚未验证完全脱离提示、从空白独立完成整套模型。
