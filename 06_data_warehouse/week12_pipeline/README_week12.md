# 第12周：可复现的简化销售数据管道

文档状态：已由学习者审核确认，2026-09-05。依据当前源码及Day1–4运行证据整理；本周Git交付尚未完成。

## 1. 业务问题与目标

当一份完整订单CSV包含新增或更正后的旧订单时，如何重新生成一致的清洗明细、数据库和渠道销售分析，而不是逐个手改结果？

本项目使用第3周的模拟脏数据，按固定顺序执行：

```text
原始CSV（20行×10列）
  → 清洗CSV（19行×18列，保留全部去重后订单）
  → 本周SQLite数据库（sales_orders，19行×18字段）
  → 筛选15笔有效订单，按渠道汇总
  → 渠道分析CSV（3行×3列）
```

业务输出回答“当前模拟样本中，哪个渠道的有效净销售额最高”。管道目标是让输入、处理规则和结果相互对应，并能重新运行；不是证明真实渠道质量或构建生产级数据平台。

## 3. 清洗与分析口径

| 环节 | 当前代码的处理规则 | 业务含义与边界 |
|---|---|---|
| 读取与文本清理 | 按字符串读取CSV，复制工作表，对全部列去除首尾空白 | 保留原始输入文件，统一文本写法 |
| 去重 | 对清理空白后的记录执行完全重复行去重；20行变19行 | 不是按订单号挑选最新版本；不同内容的同订单号冲突尚未处理 |
| 日期 | 统一中文年月日、斜杠和点号，再按年月日转换；失败或缺失保留为缺失日期 | O1006、O1012、O1017仍保留，本周总体及渠道分析不要求日期有效；不能据此直接做完整月度分析 |
| 数量与单价 | 去掉“件”“元”后转数值，无法解析时保留缺失 | “缺货”“价格待定”不能自动视作0 |
| 折扣格式 | `10%→0.1`，原数值比例保持不变，“无折扣”转0 | `discount_rate`表示折扣减免比例，10%对应按原价的90%计算净额 |
| 原始缺失折扣 | 仅对 `discount_rate_raw` 原本缺失的记录暂按0处理，同时保留原值并置 `discount_assumed_zero=True` | 当前只有O1010；这是学习练习假设，仍需业务确认，不等于已核实没有折扣；非空但无法解析的折扣不自动填0 |
| 有效分析范围 | 状态为“已完成”，且数量、单价、折扣均非缺失，标记为 `sales_amount_valid=True` | 当前15笔符合；标记和筛选不会删除清洗表中的另外4笔 |
| 金额计算 | 对全部保留记录计算折前金额和净额，之后仅将已取消订单两项正式金额置0 | 已完成但单价未知的O1011金额仍缺失，不伪装成0 |
| 渠道分析 | 在SQLite中筛选 `sales_amount_valid=1`，按渠道计算行数和净额合计，净额汇总保留两位小数并降序排列 | 当前订单号已核对无重复，才可将行数解释为订单数；不能外推到一单多行数据 |

金额公式：

```text
gross_sales = quantity × unit_price
net_sales   = gross_sales × (1 - discount_rate)
```

SQLite中的两个布尔标记存为整数0/1，缺失值存为NULL。数据库读取的是已保存的本周清洗CSV，渠道分析再通过SQL读取本周数据库，不是直接使用旧数据库或跳过入库步骤。

## 4. 如何运行

### 本机环境

- 已使用的运行入口：`D:\anaconda3\python.exe`。
- 当前环境文件元数据：Python 3.13.9、pandas 2.3.3。
- `pathlib` 和 `sqlite3` 属于Python标准库；第三方依赖为pandas。
- 当前已有输入CSV及 `outputs` 目录。脚本只打印路径检查结果，不会自动创建输出目录；在新位置复现前须准备好目录。

在PowerShell中运行完整脚本：

```powershell
& "D:\anaconda3\python.exe" "D:\data_analysis_learning\06_data_warehouse\week12_pipeline\scripts\sales_pipeline_week12.py"
```

也可在VS Code选择上述解释器后运行该文件。不要只执行脚本尾部的查询片段。

迁移到其他机器时，先准备Python环境和pandas（当前参考版本2.3.3），保留作品库目录结构，在作品库根目录运行：

```powershell
python .\06_data_warehouse\week12_pipeline\scripts\sales_pipeline_week12.py
```

这份文档核对了现有源码、文件和历史运行证据；未在新机器或全新环境重新测试。

### 运行范围与注意事项

1. 正常运行只读取原始CSV，不会自动修改或恢复它。
2. 清洗CSV和分析CSV会覆盖同名旧输出。数据库使用 `if_exists="replace"` 替换本周库内的 `sales_orders` 表，不是向表后追加。
3. 不运行旧的 `setup_sales_database.py`，也不使用旧 `sales_week4.db` 代替本周库。旧脚本会重建旧数据库，不属于本周入口。
4. CSV使用 `utf-8-sig` 输出，不包含额外DataFrame索引列；日期按年月日写出。
5. 文件被Excel或数据库工具占用、输入缺失、输出目录不存在等问题可能使流程中断。不要只因数据库文件存在就判断本次全流程成功，应确认脚本正常结束并核对结果。

当前脚本主要通过打印预览、数量和金额供人工核对。订单号无重复、文件字节一致性等还使用了额外只读核验；脚本尚未把这些检查全部实现为自动断言，不能宣称出现异常就会自动阻止发布结果。

## 7. 已知限制与能力边界

- 数据仅为20行原始模拟样本；不用于推断真实渠道效果、长期趋势或利润，也未接入成本、退款等业务数据。
- 当前有效范围只检查状态及数值非缺失，未增加数量/单价正数、折扣比例区间等完整业务校验；适用范围不能直接扩大到任意新数据。
- 只删除完全重复行，没有订单号主键约束或同订单多版本选择规则。
- 日期无效的3笔订单仍参与本周总体和渠道分析；按月分析需要另行定义有效日期范围。
- 金额使用浮点数，明细CSV可能出现较长小数，汇总时按两位小数展示；不是财务级精确货币处理方案。
- 没有调度、增量处理、自动告警、运行历史日志或跨CSV与数据库的全链原子提交。中途失败可能留下不同阶段版本的文件；修复原因后需完整重跑并复核。
- 可追溯性目前依赖保留输入、转换前字段、假设标记、代码和本次测试记录；不是自动保存每次运行全部历史版本的审计系统。
- 本周在指导下完成代码追加、修改、运行和结果验证；文件恢复由助手按授权协助，变更与恢复后的脚本均由学习者亲自运行。当前能力按“能修改验证”记录，不声称能从空白独立搭建完整管道。
