# 第10周：业务分析综合案例

## 一、项目目标

为了支持渠道资源优化与用户运营决策，本项目从渠道销售贡献、访问到加购转化、首购用户次月留存和 RFM 用户价值分层四个方面展开分析，重点判断销售贡献集中渠道、转化与留存下降来源及优先运营用户群体，并据此提出渠道优化、转化改善、用户召回与培育建议。

## 二、数据来源与适用范围

本项目包含两类练习数据：

- 渠道销售贡献分析读取 `02_sql/data/sales_week4.db` 的 `sales_orders` 表。该表包含19笔清洗后订单，查询只保留订单状态为“已完成”且销售金额有效的15笔订单。
- 漏斗、留存和 RFM 分析使用各 SQL 文件内自包含的小规模模拟数据，用于演示业务口径、SQL 结构和结果验证，不代表真实经营数据。

不同主题的数据范围彼此独立，不能把四项结果当作来自同一批用户或同一张业务事实表。

## 三、分析方法与指标口径

| 分析主题 | 核心指标或方法 | 主要口径 |
|---|---|---|
| 渠道销售贡献 | 渠道净销售额贡献率 | 各渠道有效已完成订单净销售额 ÷ 当前分析范围总净销售额 |
| 访问→加购漏斗 | 7天访问→加购转化率 | 以用户当月首次访问为起点，统计同一用户7天内首次加购；未加购用户继续保留在分母中，并归因到访问渠道 |
| Cohort 次月留存 | 首购用户次月留存率 | 用户按首次完成购买月份和首购渠道分组，判断其是否在下一个自然月再次完成购买 |
| RFM 用户分层 | Recency、Frequency、Monetary | 在2026-01-01至2026-04-01观察窗口内，以2026-04-01为基准日，计算最近购买间隔、购买次数和消费金额，再按练习阈值评分与分层 |

RFM 练习中的 `30/60天、2/4单、800/2000元` 只用于演示。真实项目应结合业务周期、用户分布、运营成本和历史效果确定阈值。

## 四、主要发现

1. 天猫净销售额为6,830.65元，贡献率47.99%，在当前有效订单样本中排名第一；抖音和京东分别贡献29.50%和22.51%。
2. 整体访问→加购率从2026年1月的71.43%下降到2月的50.00%，下降21.43个百分点；京东从100%下降到50%，是当前模拟样本中跌幅最大的渠道。
3. 首购 Cohort 次月留存率从2026年1月 Cohort 的75.00%下降到2月 Cohort 的50.00%，下降25个百分点；下降集中在京东，其留存率从100%降至0%。
4. RFM 分层中，高价值活跃用户3人，贡献6,300元、占40.13%；高价值待唤回用户2人，贡献3,900元、占24.84%；一般用户和潜力用户分别贡献22.29%和12.74%。

## 五、业务建议

- 天猫销售贡献最高，但在缺少成本、利润、退款率和获客成本时，不能仅凭销售贡献率决定继续增加渠道投入。应补充效益指标后再比较渠道资源配置。
- 京东在漏斗转化和 Cohort 留存中均出现较大下降，可优先检查渠道用户质量、访问页面体验、商品匹配和后续触达流程；由于样本极小，应先扩大数据并确认下降是否稳定，再判断原因或采取大规模措施。
- 如果当前目标是减少已有高价值用户流失，应优先运营高价值待唤回用户，设计定向召回活动；同时维护高价值活跃用户，并对潜力用户设计二次购买培育策略。

## 六、结果验证

- 渠道净销售额与总体净销售额一致，渠道贡献率合计为100%。
- 漏斗中各组加购人数均不超过访问人数，转化率均位于0%到100%。
- Cohort 留存人数不超过 Cohort 人数，渠道汇总与总体一致，并确认2月 Cohort 已有完整次月观察窗口。
- RFM 各分层用户数和消费金额能够与总体核对，金额贡献率合计约为100%，且与对照计算一致。

## 七、分析限制

- 漏斗、留存和 RFM 使用小规模模拟数据，只能验证分析方法并描述当前样本，不能直接外推真实业务表现。
- 京东漏斗和留存结果涉及极少用户，50%或0%的变化可能由个别用户造成，不能证明渠道质量真实下降。
- 渠道贡献分析缺少成本、利润、退款率、获客成本和更长时间数据，无法判断渠道盈利能力或变化是否长期稳定。
- 四个主题使用的数据范围不同，本项目展示的是一套业务分析方法，而不是对同一真实业务链路的完整因果归因。

