# AI辅助分析工作流

整理日期：2026-09-19。本页由教师依据用户第14周前四次操作与第5次两次回答整理，具体步骤名称及检查例子由教师归纳，不记为学习者从空白独立写出的完整流程。

用户补充原答：“说清楚需求，提供哪些数据，数据的口径 核对数据是否正确，结论是否与数据相吻合”。经第1级概念提示后，明确了AI生成前的信息责任和生成后的验收责任。

| 环节 | 学习者负责 | AI可以协助 |
| --- | --- | --- |
| 明确需求 | 确认业务问题、使用目的、范围与限制 | 梳理需求中的歧义，提出待确认问题 |
| 核对输入与口径 | 确认数据来源、字段、一行代表什么、有效范围及指标定义 | 查看字段、整理说明、提示可能的数据问题 |
| 提出方案与生成初稿 | 先决定分析思路，检查方案是否符合需求 | 根据已确认方案起草SQL、pandas代码或报告 |
| 审查与运行 | 检查处理逻辑，亲自运行核心学习代码，保留实际输出 | 辅助解释代码、定位报错、提出修改建议 |
| 核对与修正 | 核对计算范围、结果与明细/总体是否一致，确认修改效果 | 起草检查语句、帮助比较差异，不能把建议写成已完成验证 |
| 表达与交付 | 审核图表单位、结论证据和限制，说明自己与AI的贡献 | 整理展示和文字，协助归档可复现材料 |

A/B测试是检验措施效果的一种按需方法，不是所有描述性分析的固定步骤，也不能代替结果对账。未运行的核对、未实施的实验、未验证的原因都应明确标注状态。

五次课堂及W14-I已在提示和教师脚手架支持下完成。实际证据和能力边界见[审查报告](review_report.md)。本文件由教师整理，流程文档本身不证明从空白独立分析。
