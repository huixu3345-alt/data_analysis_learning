## 1. 业务问题与边界

根据预测时已经知道的“过去7天活跃天数”，预测会员在接下来7天是否完全不活跃。

- 一行代表一条会员模拟记录。
- 特征：过去7天活跃天数，必须在预测时点已知。
- 标签 `0`：未来7天至少活跃1天。
- 标签 `1`：未来7天完全没有活跃，是本练习关注的正类。
- 未来7天完全不活跃不等于已经证实会员永久流失。
- 数据和结果用于理解分类方法，不能直接作为真实会员运营效果证明。

## 3. 输入、处理和输出

### 输入

| 数据用途 | 记录数 | 特征 | 真实标签 |
|---|---:|---|---|
| 训练 | 8 | `[[4], [2], [0], [5], [1], [0], [3], [0]]` | `[0, 0, 1, 0, 0, 1, 0, 0]` |
| 验证 | 3 | `[[0], [3], [7]]` | `[1, 0, 0]` |

训练快照为2026-05-31，标签观察期为2026-06-01至2026-06-07；验证快照为2026-06-30，标签观察期为2026-07-01至2026-07-07。上述时间和结果均为模拟，标签观察期设定为已经完整结束。

8条记录用于训练；下文指标只在3条验证记录上计算，不是对11条记录一起评估。本例没有另设并评估独立测试集。

### 处理

1. 使用 `DummyClassifier(strategy="most_frequent")` 建立多数类基线，根据训练标签中最常见的类别预测。
2. 使用 `LogisticRegression` 从训练特征和标签学习，输出类别概率和默认预测类别。
3. 读取类别 `1` 的概率，以 `0.3` 为阈值重新生成分类结果。
4. 使用 `DecisionTreeClassifier` 学习分裂规则，将 `max_depth` 从 `1` 改为 `3` 后比较输出。
5. 在验证集上输出混淆矩阵、精确率、召回率、F1与ROC-AUC。

### 关键函数与输出

- `fit(X_train, y_train)`：用训练数据学习模型。
- `predict_proba(X_valid)`：输出每条记录的类别概率；本例 `classes_` 为 `[0, 1]`，第二列对应完全不活跃。
- `predict(X_valid)`：输出默认分类结果，而不是输出每个人相同的风险概率。
- `(inactive_prob >= 0.3).astype(int)`：把概率按指定阈值转为 `0/1` 类别。
- `export_text`：输出决策树实际学到的规则。

阈值转换这一步本身不重新训练模型；但重新运行整个脚本时，已有的 `fit` 调用仍然会执行。

第1条记录完全不活跃的预测概率约49.34%，默认0.5阈值下预测为 `0`，降低到0.3后预测为 `1`。改变的是分类规则，不是这次已经输出的概率。

### 决策树深度实验

深度上限为1和3时，实际规则相同：

```text
past_active_days_7d <= 0.50 -> class: 1
past_active_days_7d >  0.50 -> class: 0
tree_predictions: [1 0 0]
```

这里的 `0.50` 是活跃天数的分裂点，不是概率阈值。`max_depth` 是允许的最大深度，不是要求模型必须长到该深度。

训练数据中活跃天数为0的三条记录标签为 `[1, 1, 0]`，唯一特征相同，不能再靠这个特征区分；其余记录标签均为0。因此，本例加大深度上限后规则未变，不能写成“已经用本例验证深树过拟合”。过拟合和欠拟合另通过假设对照练习学习，不属于本脚本的实际对照实验。

## 5. 验证指标与解释

混淆矩阵指定类别顺序为 `[0, 1]`，行表示真实类别，列表示预测类别：

```text
                 预测0  预测1
真实0              TN    FP
真实1              FN    TP

默认阈值0.5：      阈值0.3：
[[2 0]            [[2 0]
 [1 0]]            [0 1]]
```

默认阈值下，唯一真正不活跃的会员被漏报；阈值0.3下，这条记录从漏报变为正确识别。

| 输出指标 | 输出值 | 本例含义 |
|---|---:|---|
| `recall_default` | 0.0 | 默认阈值没有找出真正不活跃的会员 |
| `precision_03` | 1.0 | 阈值0.3圈出的1条记录确实不活跃 |
| `recall_03` | 1.0 | 阈值0.3找出了唯一真正不活跃的记录 |
| `f1_03` | 1.0 | 当前精确率与召回率的调和平均为1.0 |
| `roc_auc` | 1.0 | 使用类别1概率计算，唯一正例分数高于两个负例 |

- 精确率 `TP / (TP + FP)`：预测需要提醒的名单中，实际不活跃的占比。
- 召回率 `TP / (TP + FN)`：全部实际不活跃会员中，被找出来的占比；分母不是总会员数或预测提醒人数。
- F1：精确率与召回率的调和平均，不能单独替代运营成本判断。
- ROC-AUC：考察模型区分能力，本例使用概率而非已经截断的 `0/1` 预测结果计算。

ROC-AUC为1.0与默认召回率为0.0并不矛盾：第1条记录虽然风险排名最高，但49.34%仍低于50%的分类阈值。

默认预测没有任何正例，精确率分母为0，数学上未定义；脚本没有输出该项，不把它补写为已观察到的0.0。相关零分母处理尚未作为学习者掌握内容验收。

## 6. 结果报告

本次使用8条模拟记录训练逻辑回归模型，并在3条模拟验证记录上计算评估指标。默认阈值0.5时，召回率为0.0，未识别出验证集中的不活跃会员；阈值调整为0.3时，精确率、召回率和F1均为1.0。基于模型输出概率计算的ROC-AUC为1.0。这些结果仅反映当前三条模拟验证记录上的表现，不能证明模型适合真实会员运营，真实业务效果仍需进一步评估。
